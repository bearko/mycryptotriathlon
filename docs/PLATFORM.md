# bearko.games の共通基盤・ポータルへのつなぎ込み

My Crypto Triathlon（triathlon.bearko.games）を、bearko.games のポータルと共通基盤（共通ログイン・アチーブメント・総合スコア・全体チャット・遊んだ人の数）につなぐ。共通基盤の側（bearko/MyCryptoPortfolio）は別のセッションが受け持ち、このリポジトリからは変えない。手順の正本はそのリポジトリの `docs/INTEGRATION.md` 3 章と `sdk/v1.js` の先頭のコメント。

- タイトル ID：**`triathlon`**　ホスト：**`triathlon.bearko.games`**
- 共通基盤の API は、登録したタイトルのサブドメインからの通信だけを受け付ける。**共通基盤の側の登録が本番に出るまで、SDK の通信は失敗する**（ゲームは遊べる。コンソールに失敗が出るだけ）。

## 1. 作り

| 所 | 中身 |
|---|---|
| `index.html` | `<head>` の中、ゲームの本体（Vite が `<head>` に入れる module）より前に `<script defer src="https://bearko.games/sdk/v1.js">` |
| `src/core/platform.ts` | 窓口。ほかのファイルは `window.BearkoGames` を触らず、ここの関数だけを呼ぶ。SDK の型は使うぶんだけ自前で書く（npm の依存は足さない） |
| `src/main.ts` | つなぐ（`startPlatform`）・段を送る・成績を送る・レース中はチャットを隠す |
| `src/game/meta.ts` | メダルを取ったら知らせる口（`watchFeats`） |
| `tests/platform.test.ts` | SDK が無くても例外を出さない／段の番号と id の決まり／送るアチーブメントがゲームのメダルにあること |

守ること：

- **SDK が読めない（オフライン・ブロック）・通信に失敗しても、ゲームは最後まで遊べる。** どの呼び出しも包み、失敗は `console.warn` だけ。SDK は defer なので、まだ無ければページの `load` を待ってから `init` する。
- ゲーム側は Cookie を触らない（ログイン状態は共通基盤が持つ）。
- `init({ presence: false })` にしない（来訪が止まり、KPI が数えられなくなる）。来訪（`triathlon.visit`）は SDK が最初の操作で送るので、ゲーム側の作業は無い。
- **デバッグ用の URL（`?bot=1`・`?quick=1`・`?stage=`・`?tree=`）で開いたときは、共通基盤につながない**（自動操縦や仮のスキルツリーの成績が、ランキングや人数に混ざらないように）。
- 外部の解析タグや自前のプレイログは入れていない。

## 2. はじめての人の歩み（SDK の `tutorialStep(step, id)`）

決まった手引きは無いので、**最初の 1 回の流れのどこまで来たか**を段として送る。表は `src/core/platform.ts` の `STEPS`（テストが番号と id を見張る）。

| 番号 | id | いつ送るか |
|---|---|---|
| 0 | `start` | タイトルで START を押した |
| 10 | `team` | 走順（3 人）を決めた |
| 20 | `race` | はじめての陸のレースが始まった（3-2-1 のあと） |
| 30 | `levelup` | レベルアップのカードを 1 枚選んだ |
| 40 | `gate1` | 陸の第一関門を突破した |
| 50 | `result` | 1 回の挑戦が終わった（敗退でも通過でも） |
| 60 | `tree` | スキルツリーのパネルを 1 つ習得した |
| 70 | `retry` | 2 回目以降の陸のレースが始まった |
| 90 | `done` | はじめて陸を通過した（30 位以内） |

- 同じ段は、ページの中で 1 回（窓口）、サーバーは人ごとに最初の 1 回だけ残す。
- **公開したあとは、番号と id を変えない**。段を足すときは空いている番号に入れる。
- 見たい離脱：`race` → `result`（1 回目の途中でやめた）、`result` → `tree` → `retry`（周回に入ったか）、`retry` → `done`（陸を抜けられたか）。

## 3. 全体チャット

- 画面を横いっぱいに使うゲームなので、**右のドックも 💬 のボタンも使わない**：`init({ chat: { layout: 'float', button: false } })`。
- 開くのは **タイトル画面の「💬 全体チャット」**（共通基盤につながったときだけ出る）。
- **レース中は隠す**（`chat.setVisible(false)`。紹介のカードから結果の画面まで）。結果の画面・スキルツリー・タイトルでは見える。
- 通知（アチーブメントなど）は画面の上（`toast: 'top'`）。下には決定のボタンがあるため。

## 4. アチーブメント（`triathlon.<id>`）

ゲームの中の「メダル」（`src/game/meta.ts` の `FEATS`。スキルツリーの画面に一覧）のうち、下の 10 個を共通基盤にも送る（`platform.ts` の `TROPHIES`）。**取ったときに送り、起動のたびに、これまでに取ったものも送り直す**（共通基盤に定義が無いあいだは受け付けられないので、定義が出たあとにまとめて登録される。未ログインなら仮アカウントに付き、ログインでまとまる）。

| id | 条件 | 重さの目安 |
|---|---|---|
| `gate1` | 陸の第一関門を突破する | 軽い（最初の 1〜2 回で取れる） |
| `foul` | 審判の円の中でライバルを直接攻撃して、反則を取られる | 軽い（遊び心） |
| `goal` | 陸のゴールラインを踏む | 軽い |
| `land30` | 陸を 30 位以内で通過する | **節目**（最初の大きな目標） |
| `noko` | 一度も気絶せずに陸を完走する | 中 |
| `kill300` | 1 回のレースでエネミーを 300 体倒す | 中 |
| `land1` | 陸を 1 位でゴールする | 重い |
| `sea` | 海で秘宝を手に入れる（10 位以内） | **節目** |
| `sea1` | 海で最初に秘宝を手に入れる | 重い |
| `sky` | 空のバトルロワイヤルで最後の 1 機になる（優勝） | **ゲームクリア**（`clear`） |

- 名前と絵は、共通基盤の側で MCH のスキル名から決める。節目（`land30`・`sea`・`sky`）はヒーロー、ほかはエクステンションの想定。
- 共通基盤の通知は、ゲームの結果画面の「メダル獲得」の行とは別に出る。

## 5. 総合スコア（案。口は `submitScore`）

- 種類：**1 回の挑戦ごと（`run`）**。挑戦が終わったとき（敗退・優勝のどちらでも）に 1 回だけ送る。ポーズからの「やりなおす」「タイトルへ」では送らない。
- 送る `metrics`：

| 名前 | 中身 |
|---|---|
| `cleared` | 通過した種目の数（0〜3） |
| `champion` | 空で優勝したか |
| `landPlace` / `landProgress` / `landGates` / `landQualified` | 陸の順位（1〜50。ゴールできなければ締め切り時点の順位）・進んだ割合（0〜1）・突破した関門（0〜3）・通過したか |
| `seaPlace` / `seaProgress` / `seaRelics` / `seaQualified` | 海の順位（1〜30）・潜った割合・掘り出した遺物（0〜3）・通過したか。海に進んでいなければ `null`／0 |
| `skyPlace` / `skyKills` | 空の順位（1〜10。1 が優勝）・撃墜した数。空に進んでいなければ `null`／0 |
| `kills` / `level` / `downs` | 倒したエネミー・チーム Lv・気絶した回数 |
| `timeMs` | 通過した種目の合計タイム（空はチューニングの時間を含む） |
| `tree` | 習得したスキルツリーのレベルの合計（積み上げの量。いまは点に入れない想定） |
| `regulation` / `difficulty` / `balance` | `'normal'`・`'normal'`・`1`（バランスを変えたら `balance` を上げる） |

- 計算式の案（節目の点＋成績 × 係数）：
  - 節目：陸を通過 **1,000**、優勝 **5,000**（海を通過にも 1,500 ほど置くと段が付く）
  - 成績：陸 `landProgress × 300 ＋ landGates × 100 ＋ 通過なら (50 − landPlace) × 15`、海 `seaRelics × 150 ＋ 通過なら (10 − seaPlace) × 60`、空 `(10 − skyPlace) × 150 ＋ skyKills × 120`
  - ありえない値（順位が範囲の外、`cleared` と各種目の通過が食い違う、など）は受け付けない
- 目安（自動操縦で測った値。人の手ではまだ測っていない）：
  - A（はじめの数回）：陸で 40 位前後・関門 2 つ・進み 0.8 → 成績 440 点ほど。**陸を通過して 1,000 を超える**
  - B（ふつうに優勝）：陸 20 位前後・海 5〜9 位・空 1 位で 4〜6 機撃墜 → 節目 7,500 ＋ 成績 3,000 前後で **10,000 あたり**
- 空の順位は相手しだいで振れが大きい（同じ機体で 1 位〜8 位）。係数は公開後の分布を見て直す前提。

## 6. RTA（案だけ。ゲーム側は未実装）

- 周回して育てるゲームなので、「新しいセーブから優勝まで」は数時間かかる。レギュレーションの案：
  - `triathlon-land`：新しいセーブで始める → `gate1` → `land`（はじめての陸の通過）。区切りが早く、最初に置きやすい
  - `triathlon-champion`：新しいセーブで始める → `land` → `sea` → `champion`
- IGT は実時間（SDK が測る）。挑戦の合計タイムは `timeMs` として成績にも入れてある。
- 入れるなら、タイトルに「RTA で始める」（別のセーブ枠で最初から）を足す。セーブを消さずに済むよう、枠を分ける作りが要る。

## 8. 共通基盤の側でお願いすること（まとめ）

1. `platform/trophies.js`：`GAME_HOSTS` に `triathlon: 'triathlon.bearko.games'`、`GAME_NAMES` に `MyCryptoTriathlon`、`TROPHIES` に 4 章の 10 個＋来訪（`triathlon.visit`）
2. `platform/scoring/triathlon.v1.js`（`KIND = 'run'`）と `scoring/index.js`・テストの基準プレイ
3. `js/games.js` に 7 章の行、`assets/` に画像、`index.html` の `LABEL` に `triathlon: 'Triathlon'`
4. 公開したら、ゲームを開いてコンソールに `[platform]` の失敗が出なくなること・来訪が付くことを確かめる
